# v1.5.1 — Executor-owned card check

In full card-run mode, the executor implements the card, runs its tests, and
dispatches exactly one `trellis-check` sub-agent before handing off. That
check covers the card's `base..HEAD` and in-scope uncommitted content. The
executor fixes the findings, commits them on the card, and includes the check
record in the handoff. The controller accepts the handoff. It does not
dispatch `trellis-implement` again, and it does not dispatch another
`trellis-check` while that executor session still exists.

With no independent reviewer, acceptance follows the handoff. When an
independent reviewer is declared, that read-only review runs after the
handoff and before acceptance. A failed acceptance or a failed read-only
review returns the card to the same executor session. The controller owns
rework routing, and the executor window stays until the card is accepted, as
described in `~/.skills-manager/skills/herdr-dispatch/SKILL.md`.

One worktree still has one writer at a time. The check sub-agent runs inside
the executor session and writes in sequence with the executor. Published
handoffs stay unchanged. `run handoff-check` is the remedy when the executor
session is gone and the check still has to be done; repairs on that path are
a new writable round and a new head. OCR stays once per pull request, not
once per card and not once per card commit.

Ordinary Trellis tasks that are not in full card-run mode keep the native
`trellis-implement` / `trellis-check` route.

## Downstream projects

Projects that installed `solo-github-flow` and then edited
`.trellis/workflow.md` need this card-check update in that file. Update the
card-check paragraphs and leave unrelated local text in place. Replacing the
whole workflow file would drop those local customizations. The shared wording
is the template's Phase 2.2 text from `#### 2.2 Quality check` through the
`Review scope:` line.

This note does not publish a tag. README and setup pins stay on `v1.5.0`
until a later release publish. No existing tag is moved.

## Validation and lineage

This release builds on v1.5.0. The candidate workflow is tested with the

`herdr-dispatch` skill. Ordinary Trellis tasks continue to work without it.
