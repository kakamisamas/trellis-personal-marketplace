# v1.6.1 — Fixes from the first real runs on v1.6.0

Two controller runs (Grok and Claude) on a downstream project surfaced three
frictions in v1.6.0. Nothing in the flow itself changed.

- `scripts/trellis_codegraph.py prepare` appended `/.codegraph/` to the task
  worktree's `.gitignore` even when the project already ignored `.codegraph/`
  without the leading slash, leaving a duplicate line to revert by hand. The
  helper now treats `.codegraph`, `.codegraph/`, `/.codegraph`, and
  `/.codegraph/` as the same rule.
- Phase 1.4 told the controller to run `task.py start <absolute-task-path>`
  from the coordinating base worktree. Trellis refuses a task path outside the
  current worktree's own `.trellis/tasks`, so the step now runs
  `task.py start <task-name>` inside the task worktree; the base worktree keeps
  the captured absolute paths and stays on the base branch. Phase 3.4 step 6
  clears the base pointer only when one exists.
- Phase 3.5 step 8 no longer treats a missing task worktree as an error: recent
  `gh` versions remove a sibling linked worktree together with the local branch
  during `pr merge --delete-branch`, so the worktree is often gone before the
  cleanliness check runs.

## Downstream projects

Projects on v1.6.0 that edited `.trellis/workflow.md` need the Phase 1.4
paragraph, Phase 3.4 step 6, and Phase 3.5 step 8 from this release, plus the
`scripts/trellis_codegraph.py` update from `setup.sh`. Unedited projects can
regenerate the workflow file with `--create-new` and rerun `setup.sh`.

## Installation

After the immutable `v1.6.1` tag exists:

```bash
trellis workflow \
  --marketplace gh:kakamisamas/trellis-personal-marketplace#v1.6.1 \
  --template solo-github-flow \
  --create-new
```

Review `.trellis/workflow.md.new` before switching. Run the matching
`v1.6.1/scripts/setup.sh` bootstrap for companion tools.

## Validation and lineage

This release builds on v1.6.0; no existing tag is moved. The CodeGraph helper
has a regression test for the unanchored ignore rule. The candidate workflow is
tested with the repository unittest suite.
