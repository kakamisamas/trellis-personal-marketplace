# v1.6.0 — Start runs through Phase 3.4–3.5

After the user says 「开始」, the agent runs through commit, native
finish-work, the pull request, CI, squash merge, and worktree and branch
cleanup. It stops only for a product decision, missing credentials or
permissions, a CI failure outside the task's scope, or dirty files of
unknown ownership.

Worktrees live under `<repo>-wt/`. A single-card run stays on the task
worktree and does not create a card worktree, an integration worktree, or a
new branch. `trellis_gc.py` removes a `task/*` branch only after lifecycle
evidence and a content proof. `card/*` and `run/*` are left to dispatch
`run cleanup`. Idle-task fallback archival (`--archive-idle-days`, default
7) and the sync checks before `--apply` are part of the same script. The
optional user-level turn guard is registered when `turn_guard.py` is
installed. Without that script or the config hook, the guard stays silent
and the flow is unchanged.

Projects that installed `solo-github-flow` and then edited
`.trellis/workflow.md` need these v1.6.0 paragraphs in that file. Merge them
in and leave unrelated local text in place. Replacing the whole workflow
file would drop those local customizations.

- T1 upstream merge: read-only triage in the `no_task` block (keep the two
  coordinating-worktree sentences), Guardrails, the Verification Evidence

- T2 Phase 3.4–3.5 run-through, including the user's 「开始」 as authorization

- Phase 3.5 step 9: `turn_guard.py mark-merged`, then
  `python3 scripts/trellis_gc.py --apply`, including the
  `--archive-idle-days N` sentence (default 7, `0` disables).

## Installation

After the immutable `v1.6.0` tag exists:

```bash
trellis workflow \
  --marketplace gh:kakamisamas/trellis-personal-marketplace#v1.6.0 \
  --template solo-github-flow \
  --create-new
```

Review `.trellis/workflow.md.new` before switching. Run the matching
`v1.6.0/scripts/setup.sh` bootstrap for companion tools.
